# Decision Log — World Builder / Flanker

## 2026-10-22 — Reactive condition/action sequences with explicit cancellation

**Context:** The demonstration needs six distinct tactical priorities while reusing the existing brain/body contracts.

**Decision:** Use an engine-independent reactive Selector whose children are condition/action Sequences: Retreat (own health <30%), Punish (visible player reloading or health <35%), Hold (visible player aiming at this agent), Flank, Investigate, Patrol. Re-evaluate at 5 Hz, abort the previous action before a new one executes, and fall through on action failure. Retreat and Hold retain safe stationary fallbacks when movement fails. Cover claims are released on preemption, failed paths, stuck events, target replacement, disable and death.

**Why:** Higher-priority conditions interrupt a running action immediately on the next decision tick. Reload, health and aim facts are used only while the player is perceived. Position memory expires after eight seconds; an alarm updates evidence without revealing the player's current state. Patrol has two deterministic nearby fallback destinations if no world-space waypoints are assigned. Shooting is a cooldown-limited, range/LOS-checked `IDamageable` attack and emits the existing gunshot event. If no usable side cover exists, Flank can fire from its current position; otherwise failure falls through to Investigate rather than leaving the demo inert.

**Ownership:** All new code belongs to Flanker. Core contracts and the shared AgentBody are unchanged. A local `IDamageable` health adapter bridges the missing shared enemy-health implementation; coordinate replacement with Manula later. Animation requests are issued through the body, but the existing animator's action wiring is incomplete. Death explicitly stops/disables the body and collider because `PlayAction(Die)` alone does not stop the current body implementation.

## 2026-10-22 — Custom exposure-weighted A* on welded triangle centroids

**Decision:** Create Flanker-owned geometry, graph and A* classes. Weld full triangle edges to 1 mm, reject degenerate triangles, vertex-only contacts and non-manifold edges, and validate centroid connections with Humanoid-filtered NavMesh raycasts. If a concave pair blocks the direct centroid segment, add its shared-edge midpoint as a portal node only when both portal legs are walkable. This preserves a real connection instead of falsely disconnecting the graph. Sample endpoints within 0.5 m and 0.35 m vertically, then select nearest visible graph anchors. Every output segment is checked against current walkability. Gameplay never calls Unity path search or uses NavMeshAgent.

An edge costs `EuclideanDistance * (1 + weight * meanEndpointExposure)`. Exposure is normalized to [0,1] and weight is nonnegative, so unscaled Euclidean distance to the goal is admissible and consistent. A* and UCS use the same frozen exposure snapshot. Punish uses 20% of the normal exposure weight for a more aggressive rush; Retreat retains the full weight even when the player is vulnerable. Search scans reusable arrays with a default budget of 4096 expansions, resolving ties by node ID. This simple O(V²) implementation is intended for the small greybox; record timings before replacing it with a heap. Reported graph cost excludes endpoint-anchor legs. No direct shortcut or smoothing can bypass exposure costs. The prefab reduces shared-body waypoint tolerance to 0.1 m to limit corner cutting.

**Perception limitation:** `IPlayerState` exposes root orientation but no camera pitch/FOV. Exposure approximates a 120-degree horizontal player view from the project's player-root +0.6 m eye offset. Memory freezes the last perceived facing; alarm-only evidence uses conservative omnidirectional LOS exposure. Cover protection checks torso-height occlusion; the 1.5 m greybox blocks are partial standing cover, not invulnerability. There is no crouch command in the body contract. Candidate scores combine protection height, route length and rear/side angle; retreat requires a candidate farther from the threat. Existing occupied claims are excluded.

**Dynamic navigation:** Level changes stop movement and defer graph rebuild by 0.65 seconds to allow carving to settle. A stuck event rejects its current cover for three seconds and triggers the same bounded retry. Preserve unchanged in-flight routes; a moved target triggers replacement near the next route corner after a minimum 0.75 s interval. This avoids repeatedly anchoring behind the agent mid-segment, which otherwise causes centroid backtracking. World changes and tactical preemption can interrupt immediately. Failed movement is throttled, and no walkable route produces a stationary fallback. Multiple/stacked agent meshes and off-mesh links are outside this MVP; use the existing navigation audit with Main loaded alone before testing. Existing duplicate surfaces must be reviewed manually, never silently changed by Flanker code.

## Unity verification and demonstration

1. Open Unity **6000.3.25f1** and let scripts compile. Open **Window > General > Test Runner > EditMode**; run `BlackoutProtocol.Flanker.Tests.EditMode` (37 cases: 34 pure and three component tests). The component tests require the Unity runner.
2. Open Main alone and run **Tools > Blackout Protocol > Audit Navigation**. Require 12/12 zone paths and 4/4 direct corridor crossings. The existing unbaked Environment surface and manually baked Navigation Geometry surface may produce duplicate warnings. Preserve the baked surface and asset; disable only the redundant unbaked component manually when appropriate. Do not transfer data between their differing world origins. Flanker generation does not edit surfaces or bake.
3. Run **Tools > Blackout Protocol > Create Flanker Prefab**. It creates `Assets/_Project/Prefabs/AI/Flanker/Flanker.prefab` and its blue material in a temporary additive scene, restores the prior active scene, and never saves Main. Existing output causes refusal, not overwrite. Partial output on an error is retained for inspection.
4. For a disposable demonstration, use **Save As** to create your own sandbox copy of Main before placement; keep the original Main and baked data intact. Drag the prefab into the Hub at **(-8, 0, 0)**, facing **Y=270** (toward Loading Bay). Root Y is feet height; do not use player-centre Y=1.1. The original player prefab is reused unchanged. Assign optional patrol waypoints outside the moving agent hierarchy; otherwise patrol uses cached home +/-3 m along world X.
5. Enter Play Mode. Inspect Brain `currentTactic` and shared-body path gizmos. Approach the Hub: expect Flank and blue-agent movement. Aim at it to trigger Hold; reload to preempt Hold with Punish. Shooting the player is 10 damage at most once per second, within 12 m and unobstructed LOS. To test the low-player-health condition, take damage until below 35%.
6. On the Flanker Health component, use **Flanker Debug > Apply 80 Damage (Retreat)** during Play Mode. With recent threat evidence, expect Retreat and release of the previous cover. Use **Kill** or shoot the enemy to death; expect no further movement, damage or retained cover claim. Disabling/re-enabling the brain must not leak event listeners or resurrect a dead agent.
7. Break LOS and wait eight seconds: Investigate must use the last position, then expire to Patrol without tracking the live player through walls. Move/disable a claimed cover in the disposable scene, or cause a level-change/stuck event: expect release/replan with bounded retries. Verify that a currently reloading player behind a wall cannot trigger Punish.
8. Confirm the agent takes a concealed side route when its weighted graph cost beats the shorter exposed route. Not every player position guarantees a Maintenance detour; geometry, distance and the exposed area determine cost. The focused graph test demonstrates this tradeoff independently.

The MVP is a blue capsule with ranged damage, not a finished animated android. No original scene, baked data, packages, teammate scripts or shared APIs are changed by this implementation. Real Unity compilation/import, component tests, physics, bake connectivity and playthrough checks must be distinguished from standalone managed compilation/pure tests when reporting evidence.
