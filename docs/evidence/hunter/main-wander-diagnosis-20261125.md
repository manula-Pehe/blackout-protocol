# Main Hunter Wander route diagnosis

The live Main Hunter spawned at `(8.00, 1.08, 8.00)` on a 291-node graph. `HunterBrain` referenced three shared `Enemy Spawn` transforms as Wander points: `(-18, 0, 5)`, `(20, 0, 35)` and `(36, 0, 8)`. Unity `NavMesh.CalculatePath` reported `PathPartial` for all three from the Hunter spawn while doors were closed. With the player far away and silent, `HunterBrain` repeatedly cycled these goals; one observation showed 9 route requests / 9 failures and no active route, and a later observation showed 148 requests / 143 failures. Its status was “Unreachable graph goal or search expansion limit reached.” The Main integration test timed out while waiting for animation speed before it emitted its test gunshot.

Local Main queries on the same graph succeeded from `(8, 1.08, 8)` to `(8, 0.08, 11.17)`, `(10, 0.08, 8)` and `(5, 0.08, 8)`, with equal A*/UCS costs. This points to disconnected patrol references rather than a general failure of the graph or movement. Because these are shared `Enemy Spawn` transforms, their positions were preserved. `HunterBrain.Wander` now checks NavMesh path completeness and uses a nearby reachable fallback when a patrol marker is disconnected. Door-change replanning and acoustic pursuit remain unchanged.

After the fix, a live Main observation found Hunter moving in Wander at `(6.43, 1.08, 7.46)`, actual animation speed `0.16`, three route requests and zero failures. The targeted Main integration test passed after its test-only wait was adjusted for a real door's fixed-step movement in the slow Editor runner.
